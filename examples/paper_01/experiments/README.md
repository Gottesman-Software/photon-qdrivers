# Paper 01 Reference Experiments

This directory contains the reproducible analytic-loopback evaluation,
instruction-level RTL parity, and native/MMIO board-bridge evidence for QDriver.
Their internal development labels are P3.1, P5, and P6.0, respectively; those
labels are retained in fixture metadata for traceability.

## Layout

```text
experiment_spec.json             versioned experiment inputs and tolerances
run_reference_experiments.py     dataset, acceptance, digest, and SVG generator
reference_v1/
  manifest.json                  suite and per-file SHA-256 digests
  data/                          CSV and JSON results
  figures/                       dependency-free manuscript SVGs
run_rtl_reference.py            Python-to-Icarus parity and fault harness
rtl_reference_v1/
  manifest.json                  P5 suite identity and per-file SHA-256 digests
  program.hex                    immutable six-instruction `$readmemh` fixture
  rtl_parity.json                expected/observed schedule and acquisition data
run_p6_board_reference.py        native framing, software bridge, and MMIO harness
generate_execution_plane_figure.py
                                 evidence-to-SVG and inline-table updater
p6_board_reference_v1/
  manifest.json                  P6.0 suite identity and per-file SHA-256 digests
  control_request.frame          P4 command accepted by the board bridge
  board_program.frame            P4/P5/capability-correlated instruction image
  board_result.frame             digest-bound software-board result
  control_result.frame           normalized P4 acquisition result
  bridge_summary.json            software/MMIO comparison and claim boundary
```

The committed `reference_v1`, `rtl_reference_v1`, and
`p6_board_reference_v1` directories are immutable evidence for their respective
models and contracts. If a model, generator, specification, instruction format,
register map, or testbench changes, create a new reference directory rather
than silently replacing old evidence.

## Reproduce or Verify

From the repository root:

```bash
.venv/bin/python examples/paper_01/experiments/run_reference_experiments.py \
  --verify

.venv/bin/python examples/paper_01/experiments/run_rtl_reference.py \
  --verify

.venv/bin/python examples/paper_01/experiments/run_p6_board_reference.py \
  --verify

.venv/bin/python \
  examples/paper_01/experiments/generate_execution_plane_figure.py
```

Verification regenerates the complete suite in a temporary directory and
compares every byte with the committed reference. It does not overwrite the
reference directory. The RTL harness also requires `iverilog` and `vvp`,
recompiles the testbench, compares every observed instruction field with an
independently lowered Python program, and checks the acquisition and injected
fault summaries. To generate a new suite, provide an empty output path:

```bash
.venv/bin/python examples/paper_01/experiments/run_reference_experiments.py \
  --output /path/to/new/reference

.venv/bin/python examples/paper_01/experiments/run_rtl_reference.py \
  --output /path/to/new/rtl-reference

.venv/bin/python examples/paper_01/experiments/run_p6_board_reference.py \
  --output /path/to/new/p6-board-reference
```

The harness uses the Python standard library and Photon-QDrivers; Matplotlib,
NumPy, and Pandas are not required. Figures are written directly as editable
SVG so plotted coordinates and styling remain deterministic.

The execution-plane generator validates that the six schedule-engine words are
identical to the six words in the board image, checks all displayed decoded
fields, and requires exact software/MMIO result parity before producing the
encoding and schedule figure and refreshing the two tables in the main
manuscript. It therefore fails rather than writing an ``Exact'' table row when
the underlying evidence disagrees. The manuscript update is optional: it occurs
automatically when the local Paper 01 source is present, or when its path is
supplied with `--manuscript`. The public code-only artifact does not include the
manuscript source.

## Experiments

1. A 33-point two-path phase fringe with 2,048 shots per point.
2. An 11-point loss response pooled across three seeds and 12,288 trials per
   point.
3. Integer path-delay scans across a half-open detector window.
4. Two-detector coincidence scans across an inclusive tick window.
5. An 8-bit counter and a 128-entry time-tag buffer driven through saturation.
6. Exact repeated execution using identical program, profile, seed, and job id.

The stochastic rows are deterministic pseudo-experiments generated by the
analytic sampler. Their confidence intervals characterize binomial sampling in
the model; they are not experimental uncertainty from a physical device.

## P5 RTL Reference

The P5 reference lowers six events into 128-bit words: source trigger,
modulator pulse, phase update, sync, delay, and count acquisition. The two
instructions at tick 2 test stable same-tick execution. A four-tick detector
window with a two-bit counter records three events, saturates, and reports one
dropped event. Separate loads inject an invalid format version, an unsorted
start tick, and a time-tag request to the count-only datapath; the RTL reports
error codes 1, 6, and 5 respectively.

The immutable P5 suite digest is:

```text
2df96e950badb9c0b66e66dd56716ad515b3a3887172ac7d28eab062473bde2c
```

This is instruction-level simulation evidence only. It does not establish
synthesis correctness, place-and-route timing, physical-board IO, or optical
accuracy.

## P6.0 Board-Bridge Reference

The P6.0 suite takes a real `PQDR_CONTROL_V1` frame through P4 reconstruction,
P5 lowering, capability binding, board-program framing, deterministic software
execution, normalized acquisition serialization, and an independent MMIO RTL
testbench. The software and RTL register results match exactly: final tick 11,
six instructions, channel 4, acquisition interval `[7, 11)`, three recorded
events, overflow, and one dropped event. A write to a read-only register returns
MMIO error `0x80`.

The immutable P6.0 suite digest is:

```text
9af7dfd6091f57763a0fa097938dc0eb3e5255095304f2cb687b5b38d229b1e5
```

The verifier regenerates this digest byte-for-byte under Python 3.10.18,
3.12.11, and 3.14.0.

This is board-ready software and Icarus register-interface evidence. It is not
a synthesized or deployed Red Pitaya result and contains no measured physical
timing or optical data.
